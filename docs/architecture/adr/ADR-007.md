# ADR-007: Export Bounded Opt-In Product Analytics Events

- **Status:** Proposed
- **Created:** 2026-11-08
- **Updated:** 2026-11-08
- **Containers:** `gateway`, analytics backend (operator-provided)
- **Addresses:** [`FR-012`](../../functional-requirements/fr/FR-012.md), [`QR-03`](../../quality-requirements/qr/QR-03.md)

## Context

The DevOps operator needs evidence that configured plugins are used and that a configured chat completes. Provider connectivity alone does not establish that benefit. The product has no recorded acceptance of the telemetry story yet.

## Decision Outcome

Use one registry of three events: `gateway_configuration_used`, `gateway_chat_started` and `gateway_chat_finished`. The gateway emits them only when explicitly enabled, from the parent HTTP path, through a bounded asynchronous queue. The configuration event is emitted once per application lifetime on first real chat use; its opaque `run_id` is distinct from chat run IDs. A failed or unavailable exporter is swallowed.

OpenPanel self-hosting is the default candidate for the university host; an equivalent privacy-safe backend is acceptable after host verification. One instance has two scopes, staging and production, with separate ingestion credentials. Credentials and internal URLs stay private.

## Consequences

The source guard separates web, usability-test and smoke traffic. Queries exclude only `smoke`, never synthetic traffic wholesale. Local fake-provider rehearsal proves schema and failure behavior, not adoption, campus reachability or a live dashboard. Ali must extend the deployment middleware or launcher environment with the analytics settings after this pipeline merges.

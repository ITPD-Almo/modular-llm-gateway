# ADR-001: Keep One Gateway Application For The Current Increment

- **Status:** Accepted
- **Created:** 2026-10-25
- **Updated:** 2026-10-25
- **Containers:** `gateway`
- **Addresses:** [FR-004](../../functional-requirements/fr/FR-004.md), [QR-01](../../quality-requirements/qr/QR-01.md), [QR-04](../../quality-requirements/qr/QR-04.md)

## Context

The first working interaction needs a configurable plugin gateway that can run without real keys or hosted infrastructure.
The Python service and fake provider are already in force in [v0.1.0](https://github.com/ITPD-Almo/modular-llm-gateway/releases/tag/v0.1.0), following the earlier team choice in [DEC-007](../../decisions.md#dec-007); this record documents that existing team choice on its actual creation date, rather than backdating an ADR.
An existing gateway remains a valid product option under [DEC-004](../../decisions.md#dec-004); no unique competitive advantage is inferred from building this starter.

## Considered Options

- **One Python 3.12 application using FastAPI, Pydantic and Uvicorn, with a deterministic fake provider:** retain the existing runnable baseline and one installation recipe.
- **Separate plugin service and persistent event database:** rejected for this increment because neither is needed by the synthetic workflow and each adds a deployment and lifecycle to operate.
- **Replace the current core with an existing gateway immediately:** deferred pending the matched workflow evidence and Customer reaction; existing extension support must be evaluated rather than dismissed. A later selection would supersede this record.

## Decision Outcome

Chosen option: one Python gateway application named `gateway`, with an internal fake provider and no required database or external provider.
This names every current product container: `gateway` is the entire deployable set.
The fake provider replaces only the external LLM interaction in the demonstration; it does not claim real-provider routing or credential management is delivered.
Internal plugin workers, if accepted, remain processes managed by that application rather than separately deployed containers.

## Consequences

- **Maintainability / Testability — [QR-01](../../quality-requirements/qr/QR-01.md):** a deterministic fake reply and synthetic plugins make pipeline behavior checkable without provider access. Passing offline tests does not establish real-provider behavior.
- **Flexibility / Installability — [QR-04](../../quality-requirements/qr/QR-04.md):** one environment and one command reduce the installation surface; the 15-minute independent setup target still needs an observed run.
- **Cost:** persistent logs, real-provider credentials and shared deployment are outside this baseline. The operator supplies any log collection, and future capability requirements need their own implementation and review.

# ADR-005: Deliver An Identified Image To An Operator-Provided Host

- **Status:** Accepted
- **Created:** 2026-10-25
- **Updated:** 2026-10-25
- **Containers:** `gateway`
- **Addresses:** [FR-009](../../functional-requirements/fr/FR-009.md), [FR-010](../../functional-requirements/fr/FR-010.md), [QR-01](../../quality-requirements/qr/QR-01.md), [QR-03](../../quality-requirements/qr/QR-03.md), [QR-06](../../quality-requirements/qr/QR-06.md)

## Context

The unscheduled deployment/recovery stories need a concrete target to estimate and verify.
The current product remains a local Python application; no hosting account, deployment credential or shared service is supplied by this decision.
This selects the future team implementation boundary for independent review, without claiming Customer acceptance or anticipating unpublished assignment rules.

## Considered Options

- **One identified container image transferred to an existing Linux host:** selected because the build, runtime and rollback identities can be compared without a second platform to configure.
- **Rebuild source on the destination:** rejected because the deployed result could differ from the tested artifact.
- **Provision a hosted platform or cluster now:** deferred because no account, budget or platform requirement is established.

## Decision Outcome

Use GitHub Actions to test and build one Linux/amd64 image, retain its saved archive as a workflow artifact, and transfer that same archive to an operator-provided Linux host with Docker and private SSH access.
Verify the archive SHA-256 and image identifier before running it; do not rebuild on the host.
The manifest records the full source commit, image identifier, archive checksum, configuration checksum and bundled plugin-source checksums, without credentials or user content.
The operator runs an explicit deployment command after approving the candidate; this does not depend on a paid environment-approval feature.
Keep the previous image/configuration locally until the replacement passes normal-order, changed-order, error and both-stage timeout/recovery checks; restore them with one documented command on failure.
The host endpoint and private credentials are provisioning inputs required before scheduling deployment work; no service purchase or public endpoint exposure is authorized here.
Only `gateway` runs as a product application; CI, artifact transport and the host are delivery infrastructure, not extra application/data-store containers.

## Consequences

- **Reliability / Recoverability — [QR-06](../../quality-requirements/qr/QR-06.md):** retaining the known-good image/configuration makes the five-minute synthetic recovery target runnable. This accepts interruption during replacement; it does not promise zero downtime or recovery of persistent user data.
- **Maintainability / Testability — [QR-01](../../quality-requirements/qr/QR-01.md):** the fake provider and exact archive identity allow a repeatable key-free deployment rehearsal. A local rehearsal does not establish access to a shared host.
- **Security / Confidentiality — [QR-03](../../quality-requirements/qr/QR-03.md):** credentials remain private provisioning inputs and manifests contain only identities. Trusted plugins and the host still need operator control; the image is not a security sandbox.
- **Cost:** image transfer/storage and retaining two versions use host capacity. Artifact expiry must be checked before scheduling; the operator retains the known-good copy locally rather than relying on an expired remote download.
- **Sources:** [GitHub workflow artifacts](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflow-artifacts), [Docker image save](https://docs.docker.com/reference/cli/docker/image/save/), [Docker image load](https://docs.docker.com/reference/cli/docker/image/load/). These support the transport choice, not a claim that it is implemented.

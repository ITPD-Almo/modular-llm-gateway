# ADR-002: Use Explicit Configuration And An Ordered Hook Contract

- **Status:** Accepted
- **Created:** 2026-10-25
- **Updated:** 2026-10-25
- **Containers:** `gateway`
- **Addresses:** [FR-001](../../functional-requirements/fr/FR-001.md), [FR-002](../../functional-requirements/fr/FR-002.md), [FR-003](../../functional-requirements/fr/FR-003.md), [FR-005](../../functional-requirements/fr/FR-005.md), [QR-01](../../quality-requirements/qr/QR-01.md), [QR-04](../../quality-requirements/qr/QR-04.md)
- **Decision:** [DEC-005](../../decisions.md#dec-005), [DEC-006](../../decisions.md#dec-006)

## Context

The Customer's agreed first interaction allows a restart after a plugin change and requires an explanation of inputs, outputs, order and loading.
The current product already reads a JSON list of import paths and calls dictionary request/response hooks; this record describes the choice in force, not a newly claimed Customer selection of a Python API.

## Considered Options

- **Explicit JSON import paths with two synchronous dictionary hooks:** retain configuration selection and the same visible order on both sides of the provider.
- **Automatic package discovery or live hot reload:** rejected for the current interaction because discovery and replacement add ambiguity about the active code/configuration, while restart is already allowed.
- **Policy branches embedded directly in the core:** rejected because they prevent adding an independent plugin without changing the gateway package.
- **A remote plugin protocol:** deferred because it adds packaging, transport and deployment work before a remote plugin need is established.

## Decision Outcome

Chosen option: importable no-argument plugin classes selected by `GATEWAY_CONFIG` or `config/plugins.json`, exposing `process_request(dict) -> dict` and `process_response(dict) -> dict`.
Validate configured classes at startup; apply request hooks in listed order, call the provider once, then apply response hooks in the same order.
Invalid configuration prevents startup. Runtime hook failures stop the remaining affected chain; a response-stage failure cannot undo an already-completed provider call.
The gateway's lifecycle events and a plugin's client-visible `plugin_changes` have different purposes; plugins supply their own transformation descriptions.
This choice fixes the contract and order, not cross-request mutable instance lifetime; [ADR-003](ADR-003.md) proposes the request-local execution change explicitly.

## Consequences

- **Maintainability / Testability — [QR-01](../../quality-requirements/qr/QR-01.md):** import paths and explicit stage order can be tested against synthetic classes; dictionary contents and malformed output require runtime checks, not just type hints.
- **Flexibility / Installability — [QR-04](../../quality-requirements/qr/QR-04.md):** developers add a class and configuration entry without a core edit; import visibility and restart remain required installation steps.
- **Cost:** configured imports and initial constructors are trusted executable Python. File-based configuration provides no live replacement, UI or package compatibility negotiation.

# ADR-006: Aggregate Safe Metrics In The Gateway Parent Process

- **Status:** Accepted
- **Created:** 2026-10-25
- **Updated:** 2026-10-25
- **Containers:** `gateway`
- **Addresses:** [FR-008](../../functional-requirements/fr/FR-008.md), [FR-011](../../functional-requirements/fr/FR-011.md), [QR-01](../../quality-requirements/qr/QR-01.md), [QR-03](../../quality-requirements/qr/QR-03.md), [QR-07](../../quality-requirements/qr/QR-07.md)

## Context

The future metrics story must define what is counted, how latency is compared and when totals reset.
The existing parent-generated diagnostic contract already distinguishes hook outcomes without request bodies.
No aggregate metrics endpoint or persistent monitoring store is delivered by the current implementation.

## Considered Options

- **Bounded in-memory totals in the application parent:** selected for one independently testable process with no extra deployed service.
- **A series for each request ID or arbitrary user label:** rejected because memory grows with traffic and labels can disclose input.
- **A persistent metrics database and dashboards now:** deferred because cross-process history and a monitoring platform are not needed by the small proposed comparison.

## Decision Outcome

Consume the existing allowlisted lifecycle outcomes in the parent, count each chat attempt once, and maintain thread-safe duration sums/counts and terminal outcome counters.
Expose a read-only JSON `/metrics` view with milliseconds, denominators and process-start reset documented in [FR-011](../../functional-requirements/fr/FR-011.md).
Allow at most 31 configured plugin identities plus one `other` overflow label, two stages and three terminal outcomes: at most 192 hook series.
Raw bodies, exception text, credentials, request IDs and arbitrary user labels never enter metric keys or values.
Keep totals local to one application process and reset on restart; do not imply aggregation across replicas or persistence.
The existing correlated event stream remains the detailed per-request diagnostic record under [ADR-004](ADR-004.md); aggregate totals complement it without another event format.

## Consequences

- **Performance Efficiency / Resource Utilization — [QR-07](../../quality-requirements/qr/QR-07.md):** traffic volume cannot create new request-specific series. Overflow collapses individual plugin detail after the cap, and restarting loses history; larger deployments need a later measured design.
- **Security / Confidentiality — [QR-03](../../quality-requirements/qr/QR-03.md):** the metrics boundary uses identities and numbers only. Per-request correlation remains in separately handled safe events.
- **Maintainability / Testability — [QR-01](../../quality-requirements/qr/QR-01.md):** fixed-clock sums/counts, concurrent increments, restart reset and a 10,000-request cardinality test can run without external infrastructure. A real-time delay comparison allows scheduling tolerance and is not a hard real-time guarantee.

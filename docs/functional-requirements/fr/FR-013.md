# FR-013: Export Safe Operating Signals

- **Status:** Active
- **Traces to:** [`US-12`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/111), [VP-01](../../research/value-proposition.md#vp-01)
- **Containers:** `gateway`

## Behavior

With observability enabled, the gateway shall export one structured request outcome and a matching duration observation for each completed chat request or handled chat failure, to the environment's configured observability organization. The [observability plan](../../observability.md) defines the implemented and planned signals and their queries. The record and metric labels omit prompt and reply bodies, credentials and caller data. Collection is optional.

## Acceptance Criteria

### AC-01

Given a staging gateway with export enabled, when a valid chat and a deliberate plugin timeout finish, then the staging organization returns one matching structured log point per request and a numeric five-minute P95 for the timeout series.

### AC-02

Given synthetic private strings in the request and headers, when the gateway exports logs and metrics, then neither the strings nor a client-chosen request ID is present. The gateway-generated request ID appears only in the log and response header.

### AC-03

Given export is disabled or a backend is unavailable, when a healthy configured chat is sent, then the gateway still serves it with its normal result and request ID.

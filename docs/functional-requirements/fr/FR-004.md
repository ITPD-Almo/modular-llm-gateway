# FR-004: Forward The Request And Return The Provider's Reply

- **Status:** Active
- **Traces to:** [`US-03`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/42), [`DEC-005`](../../decisions.md#dec-005), [`CON-04`](../../product-vision.md#con-04)
- **Containers:** `gateway`

## Behavior

After the last request hook, the gateway shall send the transformed request to the provider and return the provider's reply to the client after the response hooks.

When no real provider is configured, the gateway shall answer with a deterministic fake provider that needs no key and replies with the text `fake:`, a space and the content of the last message.

When the provider fails, the gateway shall return HTTP 502 with the detail `provider failed` and run no response hook.

When the request body is invalid, the gateway shall return HTTP 422 and run no hook.

Implementation status: already implemented in [v0.1.0](https://github.com/ITPD-Almo/modular-llm-gateway/releases/tag/v0.1.0).

## Acceptance Criteria

### AC-01

Given a configuration with no plugins, when a client posts a message with content `hello`, then the reply content is `fake: hello` and `provider` is `fake`, with no provider key set.

### AC-02

Given the default configuration, when the same request is sent twice, then both response bodies are identical.

### AC-03

Given a provider that raises an error, when a request is sent, then the status is 502, the detail is `provider failed` and no response hook runs.

### AC-04

Given a request whose `messages` list is empty, when it is sent, then the status is 422 and no request hook runs.

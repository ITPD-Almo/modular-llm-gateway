# FR-001: Run Configured Plugins In The Listed Order

- **Status:** Active
- **Traces to:** [`US-01`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/40), [`DEC-005`](../../decisions.md#dec-005), [`DEC-007`](../../decisions.md#dec-007)
- **Containers:** `gateway`

## Behavior

When the gateway starts, the gateway shall load each plugin listed by import path in the selected configuration file once, in the listed order.

When a chat request arrives, the gateway shall run every loaded plugin's request hook in the configuration order before calling the provider, and every response hook in the same order after the provider replies.

When the operator changes the plugin list or its order and restarts the gateway, the gateway shall apply the new list and order.

Implementation status: already implemented in [v0.1.0](https://github.com/ITPD-Almo/modular-llm-gateway/releases/tag/v0.1.0).

## Acceptance Criteria

### AC-01

Given the configuration `["gateway.plugins.add_metadata.MetadataPlugin", "gateway.plugins.uppercase.UppercasePlugin"]`, when a client posts `{"messages": [{"role": "user", "content": "hello"}]}` to `/v1/chat/completions`, then the reply content is `fake: HELLO` and `plugin_trace` is `["metadata", "uppercase"]`.

### AC-02

Given the same two plugins listed in the reverse order and a restart, when the same request is sent, then `plugin_trace` is `["uppercase", "metadata"]`.

### AC-03

Given a configuration listing only `gateway.plugins.uppercase.UppercasePlugin` and a restart, when the same request is sent, then `plugin_trace` is `["uppercase"]` and no entry in `plugin_changes` names `metadata`.

### AC-04

Given `GATEWAY_CONFIG` set to a different configuration file, when the gateway starts, then it loads the plugins listed in that file instead of `config/plugins.json`.

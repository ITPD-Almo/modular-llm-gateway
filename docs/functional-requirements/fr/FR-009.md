# FR-009: Deploy One Tested Build Through A Repeatable Pipeline

- **Status:** Active
- **Traces to:** [`US-05`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/65), [`CON-04`](../../product-vision.md#con-04)
- **Containers:** `gateway`
- **Changed:** 2026-10-25: settled the future deployment boundary and artifact identity so the unscheduled story has runnable criteria; no deployment is claimed.

## Behavior

When a commit on `main` passes the test suite, the product shall build one identified gateway artifact and deploy that same artifact to the shared environment after the documented approval.

The deployed gateway shall report the commit, the configuration and the plugin versions it runs without exposing any prompt or credential.

The target environment is one operator-provided Linux x86-64 host with a container runtime, private deployment access and a reachable demo endpoint.
The operator supplies that access before scheduling implementation; no new hosting account or paid service is required by this target.
The deployment shall use the tested artifact without rebuilding it on the destination, retain its preceding known-good artifact/configuration, and reject an artifact whose supplied checksum does not match.

Implementation status: future target, not delivered in the current release. [ADR-005](../../architecture/adr/ADR-005.md) records the selected delivery boundary; future assignment intake may revise it before scheduling.

## Acceptance Criteria

### AC-01

Given a `main` commit whose tests pass, when it is deployed, then the identifier of the deployed artifact equals the identifier of the artifact built from that commit.

### AC-02

Given a deployed gateway, when `/health` and a request through two plugins are sent to its endpoint, then both succeed and the commit and configuration identity are visible without reading a prompt.

### AC-03

Given the deployment credential's value, when the repository files, pipeline logs and public reports are searched for it, then it is found 0 times.

### AC-04

Given an artifact and its manifest containing a full source commit, image identifier and SHA-256 identities for its archive, configuration and bundled plugin sources, when the archive is changed after build, then deployment fails before replacement of the running version.

# FR-007: Bound A Slow Plugin Hook

- **Status:** Active
- **Traces to:** [`US-04`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/52), [`CON-01`](../../product-vision.md#con-01)
- **Containers:** `gateway`

## Behavior

When a plugin hook has not returned within the configured hook deadline, the gateway shall end that request with a timeout response naming the plugin and the stage, and call no later hook and no provider for it.

After a timed-out request, the gateway shall keep answering `/health` and later requests without being slowed by the timed-out hook.

Implementation status: target behavior, not implemented in [v0.1.0](https://github.com/ITPD-Almo/modular-llm-gateway/releases/tag/v0.1.0), which waits for a hook indefinitely. The default deadline of 250 ms, the timeout status code and the policy of failing the affected request rather than skipping the plugin are team proposals awaiting the Customer's verdict.

## Acceptance Criteria

### AC-01

Given a request hook that sleeps for 5 seconds and a hook deadline of 250 ms, when a request is sent, then the response arrives within 1 second with the documented timeout status and a detail naming the plugin and `request`.

### AC-02

Given a response hook that sleeps for 5 seconds and a hook deadline of 250 ms, when a request is sent, then the response arrives within 1 second with the documented timeout status and a detail naming the plugin and `response`.

### AC-03

Given either timeout above, when `/health` and then a request through healthy plugins are sent, then `/health` returns 200 and the request returns the correct reply.

### AC-04

Given 20 consecutive timed-out requests, when the last one has returned, then the number of threads and child processes of the gateway is at most 2 above its count before the first one.

### AC-05

Given the default configuration and a hook deadline of 250 ms, when the request from [FR-001 AC-01](FR-001.md#ac-01) is sent, then the reply is unchanged: `fake: HELLO`.

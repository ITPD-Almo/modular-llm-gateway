# FR-011: Report Aggregate Latency And Plugin Failure Counts

- **Status:** Active
- **Traces to:** [`US-07`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/67), [`CON-04`](../../product-vision.md#con-04)
- **Containers:** `gateway`

## Behavior

The gateway shall count requests, plugin failures and plugin timeouts, and summarize hook latency per plugin and stage, with documented units and a documented reset window.

The gateway shall label these figures only by plugin, stage and outcome, and never by prompt, response, credential or request identifier.

Implementation status: target behavior for an unscheduled candidate story; not yet fully refined.

## Acceptance Criteria

### AC-01

Given a synthetic workload of 10 normal, 3 failing and 2 timed-out requests in one window, when the figures are read, then they report 15 requests, 3 plugin failures and 2 plugin timeouts.

### AC-02

Given requests carrying synthetic secret strings, when the figures are read, then every label is a plugin, a stage or an outcome and none of the strings appears.

### AC-03

Given one run with a healthy plugin and one with the same plugin delayed by 200 ms, when their latency summaries are compared, then that plugin's summary is at least 200 ms higher in the delayed run.

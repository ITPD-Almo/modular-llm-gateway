# FR-012: Record Safe Events For The Core Chat Task

- **Status:** Active
- **Traces to:** [`US-11`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/110), [VP-02](../../research/value-proposition.md#vp-02)
- **Containers:** `gateway`

## Behavior

With analytics enabled, the gateway records the configuration's first use, the start of each validated chat, and the terminal chat outcome in the environment's analytics scope. Each event uses the [event registry](../../analytics.md#the-events) and carries the deployment-controlled source. The exporter is optional and preserves chat handling if collection is disabled or unavailable.

## Acceptance Criteria

### AC-01

Given the first validated chat with configured plugins, the environment scope receives one configuration-use, one start and one finish event matching the registry. The start and finish have the same generated attempt identifier.

### AC-02

Given a staging service configured for smoke, the raw event list shows its events, the documented metric query excludes them, and production remains unexercised. The production configuration rejects a smoke source.

### AC-03

Given synthetic request or response content, headers and credentials, only the registry fields are delivered, with no client identifiers or content. A failed backend leaves the normal gateway response available.

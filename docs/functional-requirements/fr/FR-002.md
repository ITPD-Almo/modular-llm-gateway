# FR-002: Refuse To Start With An Invalid Plugin Configuration

- **Status:** Active
- **Traces to:** [`US-01`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/40), [`DEC-007`](../../decisions.md#dec-007)
- **Containers:** `gateway`

## Behavior

When the selected configuration file is missing, is not a JSON object whose `plugins` value is a list of import paths, names a module or class that cannot be imported or constructed, or names a class without both hooks, the gateway shall refuse to start and report the configuration path and the reason.

Implementation status: already implemented in [v0.1.0](https://github.com/ITPD-Almo/modular-llm-gateway/releases/tag/v0.1.0).

## Acceptance Criteria

### AC-01

Given a configuration listing `gateway.plugins.missing.Nothing`, when the gateway starts, then startup fails with an error that contains `could not load plugins from` and the configuration path, and no request is served.

### AC-02

Given a configuration whose `plugins` value is the string `"not-a-list"`, when the gateway starts, then startup fails with an error that contains `config.plugins must be a list of import paths`.

### AC-03

Given a configuration listing a class that has `process_request` but no `process_response`, when the gateway starts, then startup fails and names that class.

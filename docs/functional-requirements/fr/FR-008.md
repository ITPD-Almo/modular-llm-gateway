# FR-008: Record Safe Plugin Lifecycle Events

- **Status:** Active
- **Traces to:** [`US-08`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/68), [`US-04`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/52), [`CON-04`](../../product-vision.md#con-04)
- **Containers:** `gateway`

## Behavior

For every hook run, the gateway shall emit one event when the hook starts and one when it completes, fails or times out, each carrying the request identifier, the plugin, the stage, the elapsed time and, on failure, a reason from a fixed list.

The gateway shall never put message content, metadata values or exception text into an event.

The gateway shall return the request identifier of every chat request in the `X-Request-ID` response header, including on error responses.

Implementation status: target behavior, not implemented in [v0.1.0](https://github.com/ITPD-Almo/modular-llm-gateway/releases/tag/v0.1.0).

## Acceptance Criteria

### AC-01

Given the default configuration, when one request is sent, then four `started` and four `completed` events appear in configuration order, request stage before response stage, all with the request identifier from the `X-Request-ID` header.

### AC-02

Given a request hook that raises an error, when a request is sent, then a `failed` event with reason `plugin_exception` names that plugin and stage, and no event appears for any later hook.

### AC-03

Given synthetic secret strings in message content, metadata and a plugin's exception text, when normal and failing requests are sent, then none of the strings appears in any event, error body or response header.

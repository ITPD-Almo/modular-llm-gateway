# FR-008: Record Safe Plugin Lifecycle Events

- **Status:** Active
- **Traces to:** [`US-08`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/68), [`US-04`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/52), [`CON-04`](../../product-vision.md#con-04)
- **Containers:** `gateway`

## Behavior

For every hook run, the gateway shall emit one event when the hook starts and one when it completes, fails or times out, each carrying the request identifier, the plugin, the stage, the elapsed time and, on failure, a reason from a fixed list.

The gateway shall never put message content, metadata values or exception text into an event.

The gateway shall generate the request identifier itself, ignoring any identifier the client sends, and return it in the `X-Request-ID` header of every chat response: successful replies, HTTP 422 validation errors, plugin failures (500), provider failures (502), unavailable workers (503), timeouts (504) and oversized payloads (413).

The gateway shall not copy request content into a validation error.

Implementation status: target behavior, not implemented in [v0.1.0](https://github.com/ITPD-Almo/modular-llm-gateway/releases/tag/v0.1.0). The validation-error cases are not yet covered by the proposed runtime.

## Acceptance Criteria

### AC-01

Given the default configuration, when one request is sent, then four `started` and four `completed` events appear in configuration order, request stage before response stage, all with the request identifier from the `X-Request-ID` header.

### AC-02

Given a request hook that raises an error, when a request is sent, then a `failed` event with reason `plugin_exception` names that plugin and stage, and no event appears for any later hook.

### AC-03

Given synthetic secret strings in message content, metadata and a plugin's exception text, when normal and failing requests are sent, then none of the strings appears in any event, error body or response header produced by the gateway.

### AC-04

Given a request whose `messages` list is empty and whose `metadata` carries a synthetic secret string, when it is sent, then the status is 422, the response has an `X-Request-ID` header, and the body does not contain the secret.

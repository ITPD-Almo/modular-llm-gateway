# FR-003: Accept Plugins Through The Documented Hook Contract

- **Status:** Active
- **Traces to:** [`US-02`](https://github.com/ITPD-Almo/modular-llm-gateway/issues/41), [`DEC-006`](../../decisions.md#dec-006), [`CON-01`](../../product-vision.md#con-01)
- **Containers:** `gateway`

## Behavior

The gateway shall accept as a plugin any importable class that can be constructed without arguments and provides a `process_request` hook and a `process_response` hook, each taking one dictionary and returning a dictionary.

The gateway shall pass the first request hook only the validated request fields `model`, `messages` and `metadata`, pass the first response hook the provider's reply, and pass each later hook the dictionary returned by the hook before it.

When a new plugin class outside the gateway package is added to the configuration and the gateway restarts, the gateway shall run that plugin without any change to the gateway's own files.

Implementation status: already implemented in [v0.1.0](https://github.com/ITPD-Almo/modular-llm-gateway/releases/tag/v0.1.0).

## Acceptance Criteria

### AC-01

Given a plugin class defined in a module outside `gateway/` and listed in the configuration, when the gateway restarts and a request is sent, then that plugin's hooks run and `git diff -- gateway/` is empty.

### AC-02

Given a plugin whose request hook replaces every message's content with `AAAA` and whose response hook replaces the reply content with `BBBB`, when a request with content `hello` is sent, then the fake provider receives `AAAA` and the client receives `BBBB`.

### AC-03

Given a client request that also contains `plugin_trace` and `plugin_changes` fields, when it reaches the first request hook, then neither field is present in the dictionary that hook receives.

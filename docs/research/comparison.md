## Reading the table as a whole

Based on ALT-01 and ALT-02 only; to be revisited once ALT-03 is in.

- **Custom policies come with a trade-off (P1).** ALT-01 offers in-process TypeScript plugins only in the open-source gateway, which requires a build step and lacks the hosted governance features; its hosted product runs custom logic as webhooks (latency, fail-open by default). ALT-02 runs custom logic in-process on the hosted service, but in XML with C# expressions that get only limited verification when saved.
- **Company-specific sensitive data relies on regex in both (P4).** ALT-01 has fixed PII patterns plus regex checks; ALT-02 has no PII policy but allows `Regex.Replace` in expressions. Regex handles identifiers with a fixed format (employee numbers, project codes), but not confidential content without a fixed shape, and each company writes and maintains its own patterns.
- **Governance follows the vendor's pricing or cloud (P2, P5, P6).** ALT-01 gates SSO, admin audit, and VPC hosting behind Enterprise; ALT-02 gates features by tier and ties hosting to Azure.
- **Routing is not a differentiator (P3).** Both already cover fallback, weighting, and conditions; building a better router is unlikely to be valued.

These are inputs to `gap-analysis.md`, not gaps yet: each still needs the four gap tests.

# QR-03: Keep Request Content Out Of Diagnostics

Nothing the gateway itself writes for diagnosis or returns as an error contains the content of a request or a response.

- **Status:** Active
- **Characteristic:** Security
- **Sub-characteristic:** Confidentiality
- **Business importance:** Medium
- **Technical risk:** Medium
- **Changed:** 2026-10-25: made the future aggregate-metrics boundary explicit during backlog refinement; no metrics implementation is claimed.

## Scenario

### Source

An operator or a support engineer who reads the gateway's diagnostics to find a failed plugin.

### Stimulus

Requests whose message content and metadata carry synthetic secret strings pass through the gateway, and some of them fail or time out in a plugin.

### Environment

Normal operation with the default diagnostics output, a plugin that raises an exception whose text includes the secret, and a plugin that returns an invalid value.

### Artifact

The gateway's own diagnostic events, its HTTP error responses, its response headers and its future aggregate metrics. Output that trusted plugin code writes directly, such as a plugin's own log lines, is outside this artifact.

### Response

The operator can tell which plugin failed, at which stage and for which request, without seeing any message content, metadata value or exception text.

### Response Measure

Across 5 synthetic secret strings sent through normal, invalid-body, failing, invalid-output and timed-out requests, 0 occurrences of any secret appear in the diagnostic output, the HTTP error bodies, response headers or future metrics output.

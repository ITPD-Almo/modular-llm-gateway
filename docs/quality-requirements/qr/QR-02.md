# QR-02: Keep Serving After A Plugin Hangs

A plugin hook that never returns fails only the request it is processing, and the gateway serves the next request normally.

- **Status:** Active
- **Characteristic:** Reliability
- **Sub-characteristic:** Fault Tolerance
- **Business importance:** High
- **Technical risk:** High

## Scenario

### Source

A badly written third-party plugin loaded from the configuration file.

### Stimulus

The plugin's request hook or response hook sleeps for 5 seconds instead of returning.

### Environment

Normal operation on one gateway instance with a hook deadline of 250 ms. The 250 ms deadline and the 1-second bound below are team proposals that the Customer has not yet confirmed.

### Artifact

The gateway's request pipeline and the configured plugin chain.

### Response

The affected request ends with the documented timeout outcome that names the plugin and the stage, and later requests are processed as if the slow plugin had not run before.

### Response Measure

The affected request receives its timeout response within 1 second, `/health` returns 200 within 1 second afterwards, and 10 of 10 following requests through healthy plugins return the correct response. After 20 consecutive timed-out requests, the number of threads and child processes of the gateway is at most 2 above its count before the first one.

# QR-06: Restore A Known-Good Synthetic Deployment Within Five Minutes

An operator restores the preceding identified image and configuration and passes the smoke checks within five minutes of starting recovery.

- **Status:** Active
- **Characteristic:** Reliability
- **Sub-characteristic:** Recoverability
- **Business importance:** Medium
- **Technical risk:** Medium

## Scenario

### Source

The operator of the future shared demonstration host.

### Stimulus

A new image fails at least one post-deployment smoke check.

### Environment

An operator-provided Linux/amd64 host with Docker, reachable private deployment access, the previous known-good image/configuration already retained locally and no persistent user data or real provider key.

### Artifact

The gateway deployment and its documented restore command.

### Response

The failed candidate remains marked failed; the operator restores the previous image/configuration and runs normal-order, changed-order, plugin-error and request/response timeout-recovery checks against its endpoint.

### Response Measure

Within 300 seconds of starting the restore command, the endpoint reports the preceding image/source/configuration identities and every smoke check passes; a deliberately broken candidate is never reported healthy.
This is a future target, not a measured result of the current local release.

# QR-01: Check The Plugin Pipeline Without A Provider

Every behavior of the plugin pipeline can be checked by automated tests that need no network access and no provider key.

- **Status:** Active
- **Characteristic:** Maintainability
- **Sub-characteristic:** Testability
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

A team member who changed the gateway core or the plugin contract.

### Stimulus

The team member runs the test suite after a change to the request pipeline, the configuration loader or the plugin contract.

### Environment

A clean clone on Python 3.12 with the documented test dependencies installed, no `.env` file, no provider key and no network access.

### Artifact

The critical gateway modules: the request pipeline in `gateway/main.py`, the configuration loader in `gateway/config.py`, the plugin contract in `gateway/plugins/base.py`, and the default plugin list in `config/plugins.json`. Once the proposed runtime is merged, also its hook execution in `gateway/execution.py`, its output validation in `gateway/validation.py` and its lifecycle events in `gateway/diagnostics.py`.

### Response

The suite runs every pipeline behavior against synthetic plugins and the fake provider, and reports which behavior passed or failed.

### Response Measure

`python -m pytest` finishes in under 60 seconds with zero outbound network connections, and each pipeline requirement from [FR-001](../../functional-requirements/fr/FR-001.md) to [FR-008](../../functional-requirements/fr/FR-008.md) has at least one test that fails when that behavior is removed. Deployment and metrics requirements are checked by their own testing plan, not by this scenario.

## QRT-01

The product CI runs the whole test suite from a clean checkout, with no `.env` file, no provider key and no provider call, and fails when a critical module breaks.

- **Status:** Active
- **Level:** CI
- **Runs at:** the `Tests` step of the `test` job in [`.github/workflows/tests.yml`](https://github.com/ITPD-Almo/modular-llm-gateway/blob/main/.github/workflows/tests.yml), on every pull request and every push to `main`.

### Procedure

1. Open the latest `Tests` workflow run for the commit under test in the repository's Actions tab.
2. Open the `test` job and its `Tests` step, which runs `python -m pytest` on a fresh GitHub-hosted runner after `python -m pip install -e ".[test]"`.
3. Read the step's conclusion and the last line of its log, which prints the number of passed and failed tests and the elapsed time.
4. To repeat it by hand, clone the repository into an empty directory on Python 3.12, run `python -m pip install -e ".[test]"`, and run `python -m pytest` with no `.env` file and no provider key.

The suite has at least one test for each critical module the scenario names: `tests/test_gateway.py` for `gateway/main.py`, `tests/test_plugins.py` for `gateway/config.py`, `gateway/plugins/base.py` and `config/plugins.json`, `tests/test_execution.py` for `gateway/execution.py`, `tests/test_validation.py` for `gateway/validation.py`, and `tests/test_diagnostics.py` for `gateway/diagnostics.py`.

**Pass when:** the `Tests` step concludes with success, its last line reports 0 failed tests, and the elapsed time it prints is under 60 seconds.
